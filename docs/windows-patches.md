# Fork-only patches

The patches this fork adds on top of [upstream's catalog](patches.md). Upstream's file is not edited here (see "Rule: never edit upstream files in place" in the repo's `CLAUDE.md`), so a feature that exists only in this fork is listed on this page instead. Each row links the patch source; the mechanism is documented in the source's header.

| Patch | What it does & why it exists |
|---|---|
| [`add_cache_warm.nim`](../patches/windows/add_cache_warm.nim) | **Cache warmer** (opt-in, off by default). Sends one short turn to an idle Code session shortly before its prompt cache would lapse, so your next message still reads the cache instead of paying for a rewrite. Settings -> Extra -> Community Features -> *Cache warmer*: a switch, *stop after N hours without a message* (1-24, default 3) and *stop after N cache rewrites' worth of spend* (0-10, default 1, 0 = no limit); the key is `cacheWarm` = `{enabled, hours, rewrites}` in `claude-desktop-extra.json`, and a valid object in the `.jsonc` wins and locks the row. It reads the cache tier (1h or 5m) from each turn's usage, pokes about 5 minutes (1h) or 1 minute (5m) before expiry, charges each poke its real usage, and stops at a poke that missed the cache. Pokes are ordinary turns: they show in the chat and use a little quota. Log lines: `[cache-warm] <session> poke\|skip(<reason>) ...` in `claude-patches.log`. Policy in [`js/cache_warm.js`](../js/cache_warm.js); tests `scripts/tests/windows/test-cache-warm*.mjs` |
| [`add_windows_profiles.nim`](../patches/windows/add_windows_profiles.nim) | `--profile=NAME` and sign-in callback routing for the Windows build |
| [`add_usage_status.nim`](../patches/windows/add_usage_status.nim) | Usage and session status, a port of UI+ for Claude: a usage and pace readout in claude.ai chat pages, behind the `usageStatus` switch (see [usage-session-status.md](usage-session-status.md)) |
| [`add_files_activity.nim`](../patches/windows/add_files_activity.nim) | **Files tab activity** (opt-in, off by default; key `filesActivity` in `claude-desktop-extra.json`, a value in the `.jsonc` wins and locks the row). While Claude works, each new `Read`, `Edit`, `MultiEdit`, `Write` or `NotebookEdit` on a file under the session folder makes the Code tab's Files panel open the folders down to it and scroll there (upstream's own `followInFilesTree`), and the file name shimmers for 2.7 seconds: purple for reads, orange for edits, with folders that had to be opened in a dimmer shade. It works inside one session folder (for example a home folder holding many repos) without changing the session folder. Files outside the session folder, including added directories, are skipped and logged once as `[files-activity] outside`. Opening or switching to a session never follows its history. The page script finds the Code tab's transcript and Files stores through React fibers (`js/files_activity_page.js`); a missing store logs `[files-activity] stores` to `claude.ai-web.log` and the feature idles. Not in this version: the commit tint (green), light-theme palettes, the file icon tint and an age column. Tests `scripts/tests/windows/test-windows-files-activity-*.mjs` |
| [`add_windows_update_notice.nim`](../patches/windows/add_windows_update_notice.nim) | Once-per-version dialog when a newer `windows-v` release is out (the Windows build has no updater) |

The settings half of the cache warmer and of Files tab activity (the key, its channels, the page row) lives in upstream files, so it is applied at build time by `scripts/windows/overlay/20-extra-settings.patch`; the Makefile dependency for `js/cache_warm.js` is in `10-build-plumbing.patch`. The patch and its tests live in `patches/windows/` and `scripts/tests/windows/`, which upstream's patch and harness counts do not include.
